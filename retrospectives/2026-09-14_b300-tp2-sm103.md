## Five whys (primary chain)

1. **Why did GLM-5.3 fail to serve on 2x B300?**
   vLLM's DSA sparse-attention indexer kernel `cooperative_topk` has no
   sm_103 SASS in any published wheel; GLM-5.3 (deepseek_v32 arch) calls it
   during the init profile run. Evidence: pod-side traceback + wheel grep.
2. **Why does the kernel lack sm_103?**
   vLLM wheel builds compile a TORCH_CUDA_ARCH_LIST that omits 10.3 while
   including sm_100/sm_120. Unknown (external): why the build matrix skips
   B300 — not resolvable from this workstation; workaround recipe adopted.
3. **Why did isolation take ~2.5h?**
   (a) The arch-list evidence genuinely supported an over-broad wrong
   conclusion; (b) the falsifying experiment (single-GPU probe) was only
   invented after burning a full 433 GB download on the wrong image; (c) the
   patch loop then misread our own tooling failure as a second broken kernel.
4. **Why did we trust arch lists over an empirical probe?**
   The workflow had no "verify the GPU op empirically before structural
   changes" step, and the local-docker arch check measures the same
   misleading signal — the cheap decisive experiment (1x B300 probe pod +
   `torch.zeros(8,device='cuda').sum()`) was discovered late, not absent.
5. **Why did our own patch produce a misleading error?**
   The patch used `current_platform.is_device_capability()`, whose pynvml
   call raises a bare 'Invalid Argument' inside TP workers — textually
   identical to a CUDA launch failure. Root: iterated on the error text
   without reading the deepest stack frame each cycle.

**Sufficient root cause (supported):** an upstream wheel gap (missing sm_103
DSA kernels) interacted with two local process gaps — no cheap empirical
verification before expensive structural moves, and error-surface triage that
didn't always read the innermost frame.

## Root-cause categories

- Infrastructure Gap (external): vllm wheel build matrix lacks sm_103 DSA kernels.
- Process Gap (ours): empirical-probe-before-structural-change not institutionalized.
- Observability Gap: multiproc_executor surfaces only wrapper errors from workers.
- Testing Gap: bench does not pre-flight endpoint reachability/window before running.

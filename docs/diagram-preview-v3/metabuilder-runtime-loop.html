MetaBuilder Runtime Loop

Question. How does the controller plan, execute, observe, verify, recover, and stop without mixing effects with state?

Where we are. This is the runtime view. The functional core computes intents and state transitions; effect interpreters perform admitted work and return controller observations.

Constructs and ownership
  • The controller owns RunState, intent persistence, observations, transitions, checkpoints, and stopping.
  • The broker admits effects against authority and resources.
  • Interpreters perform effects but cannot transition state directly.
  • Recovery reconciles ambiguous outcomes before any retry.
Reading the shapes
Stadium: actor, entry, or terminal outcome. Rectangle: callable or pure function. Cylinder: immutable typed value or durable record. Blue border: current or established. Green border: proposed or missing. Orange border: current but needing improvement. Yellow box: standing rule or evidence boundary.
Relationship convention

Solid arrows show a currently supported relationship. Dashed arrows show a proposed, weakly typed, indirect, or not-yet-supported relationship.

Plain-language glossary
  • Reducer: a pure function from state and event to new state or stop reason.
  • EffectOutcomeUnknown: an operation may have happened, so blind retry is unsafe.
  • Interpreter: the runtime adapter that performs an admitted effect.
